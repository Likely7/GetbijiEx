# 技术决策记录

> 最后更新：2026-07-26

本文记录已经确定并影响后续维护的关键决策。若要改变某项决策，应新增一条替代记录，不直接删除历史原因。

## ADR-001：使用独立且持久化的 Chrome 配置

**状态：** 已采用  
**背景：** 直接复用日常 Chrome 容易遇到调试端口冲突和用户浏览器控制问题；临时浏览器配置又会丢失登录态。  
**决策：** GetbijiEx 使用自己的 Chrome user-data 目录和固定候选调试端口。  
**结果：** 用户首次登录后可长期复用 Cookie；各用户的登录态仅保存在各自电脑。JWT 短期过期时通常无需重新登录。

## ADR-002：JWT 过期时自动刷新并重试一次

**状态：** 已采用  
**背景：** Biji JWT 大约 30 分钟过期，不能把过期视为异常故障。  
**决策：** GUI 列表请求遇到认证错误时自动启动 Token 捕获并重试原动作一次，同时设置防循环标记。  
**结果：** 降低用户操作成本，并避免刷新失败造成无限重试。

## ADR-003：Tkinter 工作线程通过队列回到主线程

**状态：** 已采用  
**背景：** macOS Tkinter 从工作线程直接调用 UI 调度存在界面不恢复的问题。  
**决策：** 后台线程只把回调写入 `queue.Queue`，主线程每 100 毫秒轮询并执行。  
**结果：** 网络请求和导出不会冻结 GUI，控件状态可以可靠恢复。

## ADR-004：同一可执行文件同时提供 GUI 和 CLI

**状态：** 已采用  
**背景：** 普通用户需要双击应用，Agent 需要稳定的命令行接口；分成两个安装包会增加分发和路径管理成本。  
**决策：** 统一入口无参数时启动 GUI，有参数时进入 JSON CLI。  
**结果：** 一个安装包同时服务普通用户和 Agent，Skill 可以直接调用应用内可执行文件。

## ADR-005：CLI stdout 只输出 JSON

**状态：** 已采用  
**背景：** Agent 需要可靠解析命令结果，导出模块原有进度信息会污染 stdout。  
**决策：** 结构化结果只写 stdout；过程日志和进度写 stderr；认证和取消使用明确退出码。  
**结果：** Skill 和其他自动化程序不需要从混合文本中猜测结果。

## ADR-006：Skill 随应用打包并支持多 Agent 安装

**状态：** 已采用
**背景：** 单独维护 Skill 仓库会增加版本漂移，小白用户也难以手动配置调用路径。
**决策：** `skills/getbijiex/` 作为唯一 Skill 来源并随应用打包；GetbijiEx 自带安装器会复制完整目录，并把默认 npx 启动区块替换为真实 CLI 路径；预设 Claude Code、Codex，并允许 `--dir` 指定其他 Agent 目录。
**结果：** Skill 与应用版本同步，GUI、GetbijiEx CLI 和标准 Agent Skills 安装工具都能完成安装。

## ADR-007：应用数据使用操作系统标准目录

**状态：** 已采用  
**背景：** 配置、Chrome 登录态和导出结果不应依赖源码目录，也不能写入只读的应用包。  
**决策：** macOS 使用 `~/Library/Application Support/GetbijiEx`，Windows 使用 `%APPDATA%\\GetbijiEx`，Linux 使用 `~/.local/share/GetbijiEx`。  
**结果：** 打包版和源码版共享稳定数据位置；旧 `BijiExportApp` 目录在新目录不存在时自动迁移。

## ADR-008：按目标操作系统原生构建

**状态：** 已采用  
**背景：** PyInstaller 不支持从 macOS 直接交叉编译 Windows 可执行文件。  
**决策：** 本地脚本负责当前平台构建，GitHub Actions 在 macOS 和 Windows runner 上分别构建产物。  
**结果：** 两个平台均可生成原生包；正式发布前仍需在真实设备上进行功能验收。

## ADR-009：公开仓库不保留认证文件历史

**状态：** 已采用  
**背景：** `config/biji_auth.json` 曾进入本地 Git 历史，公开推送会泄露认证信息。  
**决策：** 文件加入 `.gitignore`，并在首次公开推送前清理全部待推送历史。  
**结果：** 当前公开仓库与构建产物不包含认证文件；后续发布检查必须继续验证。

## ADR-010：使用标准 Agent Skills CLI 分发独立 Skill

**状态：** 已采用
**背景：** 用户需要一条可以直接复制的 npx 命令，但项目尚无正式 GitHub Release；此时发布自有 npm 软件安装器会引入二进制下载、校验、平台版本和 npm 发布权限等额外依赖。
**决策：** 仓库使用标准 `skills/getbijiex/` 结构，通过 `npx skills add Likely7/GetbijiEx --skill getbijiex` 从 GitHub 分发 Skill。原样安装的 Skill 携带 Node 启动器，用于定位标准安装位置、PATH、环境变量或用户明确配置的 GetbijiEx；为避免执行当前项目中的不可信脚本，不自动信任工作目录里的同名源码。本阶段不发布 `npx getbijiex` 软件安装器。
**结果：** Skill 可以在没有自有 npm 包和正式 Release 的情况下单独安装，同时保留“Skill 不等于软件本体”的边界。正式 Release 完成后，再独立评估通过 npm 下载和校验应用程序。
