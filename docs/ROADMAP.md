# 路线图

> 最后更新：2026-07-26

## 优先级定义

- **P0**：发布阻断问题，不解决就不能公开发布。
- **P1**：应在近期版本完成，显著影响可靠性或用户体验。
- **P2**：优化项，不阻断当前版本。

## 阶段一：核心产品闭环（已完成）

- [x] 自动捕获并保存 Biji Token。
- [x] 使用独立 Chrome 配置持久化 Cookie 和登录态。
- [x] 自动加载知识库与博主列表。
- [x] 选择博主后导出 Markdown 和 JSON。
- [x] 增加导出进度和输出目录管理。
- [x] 提供 JSON CLI 和 Agent Skill。
- [x] 支持 Claude Code、Codex 和自定义 Skill 目录。
- [x] 完成 GetbijiEx 品牌改名与旧数据目录迁移。
- [x] 建立 macOS、Windows 自动构建流程。
- [x] README 提供可直接复制给 Agent 的安装和单独安装 Skill 提示词。

## 阶段二：首个公开版本（当前阶段）

### P0

- [ ] 在 Intel Mac 上验证或增加 `x86_64` / universal2 macOS 构建。
- [ ] 在真实 Windows 10/11 设备上完成 GUI、Chrome 登录、Token 捕获和导出的端到端验收。
- [ ] 明确首个版本号，创建 Git tag 和 GitHub Release。
- [ ] 为 Release 提供 macOS、Windows 下载包和校验值。
- [ ] 按 [发布检查清单](RELEASE_CHECKLIST.md) 完成完整验收。

### P1

- [x] 给 Windows 用户补充 SmartScreen 和首次运行说明。
- [x] 给 macOS 用户补充未签名应用的首次打开说明。
- [ ] 在 CI 中增加自动测试步骤，构建前先运行 `pytest`。
- [ ] 增加失败导出的可恢复机制或失败条目清单。
- [ ] 改善窄窗口、小屏幕和系统字体放大时的 GUI 布局。

## 阶段三：稳定性与维护性

### P1

- [ ] 清理未使用依赖，降低安装与打包体积。
- [ ] 为 Token 自动刷新和 GUI 队列补充更完整的单元测试。
- [ ] 增加结构化日志和可复制的错误诊断信息。
- [ ] 为 Biji API 响应结构增加防御性校验，减少接口变化导致的模糊错误。

### P2

- [ ] 支持批量选择多个博主导出。
- [ ] 支持断点续传或跳过已导出的笔记。
- [ ] 增加导出文件命名模板。
- [ ] 增加应用版本显示和“检查更新”入口。
- [ ] 评估其他 Agent 的标准 Skill 目录并提供预设。

## 维护规则

- 新任务先写入本路线图或对应 GitHub Issue，再进入实现。
- 完成项需有代码、测试或验收记录，不以“已写代码”作为完成依据。
- 每次发布后更新项目状态、路线图和发布检查清单的执行结果。
- 外部 API 行为变化应记录在技术决策或故障记录中，避免重复调查。
